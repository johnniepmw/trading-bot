## Goal
A pure, tested core that runs the same in backtests and live: daily data in, a long-or-cash
trend rule (ADR-0015) to target weights, orders through a risk layer with a veto, against
a fake broker, with a validated backtest. No Trading 212 adapter (the owner's API check is
pending) and no GCP work (Phase 2).

## Rollout and rollback
- Kill switch `new-orders` (fails closed). Nothing is deployed or traded in Phase 1; each PR reverts cleanly.

## Decisions
- Split into seven PRs so each reviewable change is small and risk classes stay separate.
- Strategy parameters are frozen in the spec first (Faber's 10-month rule, 210 trading days, 25% cap, 10% volatility cap, 0.15% cost per side). The values are the published defaults, not fitted.
- ADR 0015 is accepted now because the owner already chose the strategy family; the gate criteria are the plan's own proposals, written before results so they can be changed only before the hold-out opens.
- Backtests of engine code use synthetic prices committed to the repo; real market data stays out of the repo (licensing and ADR-0014 hygiene).
- Universe tickers are candidates only; instruments are data, confirmed after the owner's API check.
- Risk constants (position cap, drawdown levels) are proposed in PR 3's brief for the owner's `/approve-risk`.

## Open questions (work continues on the defaults meanwhile)
1. **Gate criteria** (strategy spec, "Gate"): net Sharpe above 0.5, significant Deflated Sharpe, simulated 95th-percentile drawdown within 20%. — default: as written. Changeable only before the hold-out is opened.
2. **Price history source for PR 7.** Real daily bars for the seven ETFs are needed and Trading 212's API has none. — default: you run a small export script (I'll write it, stdlib only) in Cloud Shell using Yahoo Finance CSV downloads and keep the files in a private bucket, never in the repo. Alternative: a paid vendor. Cost to undo: low until PR 7.
