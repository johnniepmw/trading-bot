# Tech debt

Things noticed but deliberately left out of scope. One line each, newest first.
Format: `- YYYY-MM-DD <area>: <problem> — <impact> — <suggested fix>`

- 2026-11-22 ledger: no owner command raises the high-water mark after a deposit of more than about 10% (runs stop with "implausible new peak"), or lowers it deliberately before a withdrawal — the owner has to ask the agent each time — add an owner-only job command (`mark --set <GBP>` with the broker's equity check, logged), reviewed as high risk
- 2026-11-22 staging: setup refuses where a ledger ever existed (soft-deleted included), so staging's ledger can't be reset in place (staging-ledger-reset.md) — testing from a clean state means a 30-day wait — add a staging-only reset path that the prod wiring refuses
- 2026-11-21 agent-review (pre-existing, high): the required `agent-review` check is matched by name only, so a workflow on any branch with `checks: write` could create a passing `agent-review` check run on a PR head (the `risk-gate` status is now pinned to its own app; see docs/runbooks/risk-gate-app.md) — post the verdict through a dedicated app too and pin `integration_id` to it
- 2026-11-21 risk-gate (pre-existing): `main()` reads `head.sha`, then the file list, and sets the status on the first SHA without re-checking the head, so a quick push of a harmless commit can earn success for a malicious one that is force-pushed back (its old CI and review results are still green) — re-fetch the PR after listing files and set no status if `head.sha` changed
- 2026-11-21 dependabot: the tag check accepts any upstream tag, so a "bump" to an older release with a known vulnerability is still standard — require the new `vX.Y.Z` to be greater than the old one
- 2026-11-21 risk-paths: `tests/scripts/**` pins down gate behaviour but is standard risk, so a later PR could weaken those tests without approval — add it to `.github/risk-paths.txt`
- 2026-11-21 kit escalate skill: says the owner comments `/approve-risk <first 7+ chars>`; risk-gate now needs the full 40-character SHA — change it upstream in the kit repo, then `make kit-sync`
- 2026-11-21 secret scan: gitleaks runs `git log -p` without `-m`, so a secret introduced only in a merge commit inside a PR's range isn't scanned on the PR (the squash commit is scanned on main, after it's public) — pass `-m` or scan the merge ref's diff too
- 2026-11-21 agent-review: the "Prepare review inputs" and "Post the review report" steps run the PR's own `scripts/risk_classify.py` and `scripts/pr-comment.sh` in the job that holds `CLAUDE_CODE_OAUTH_TOKEN` and a `pull-requests: write` token; a background process started there could outlive the step, read the token or overwrite `verdict.json` — mitigated because `scripts/**` is high risk (needs `/approve-risk`) and fork PRs get no secrets — run those two scripts from a separate base-branch checkout
- 2026-11-21 python: Dependabot ignores python minor/major base-image bumps, so nothing signals when 3.13 nears end of life (Oct 2029) and its `3.13-slim` digest stops getting fixes — security fixes stop silently — plan a deliberate Python upgrade (Dockerfile, `mise.toml`, `pyproject.toml` together) well before then
- 2026-11-21 kit upgrade docs: the template's v0.1 → v0.2 upgrade steps don't warn that `.claude/settings.json` hooks are re-read live and fail closed — pointing them at `.claude/hooks/*.sh` before those files exist blocks every tool call and locks the session out — say in the template's upgrade instructions to run `scripts/kit-sync.sh` and switch the hooks block in one command (upstream, in agentic-dev-template)
- 2026-11-22 template bootstrap (upstream): on a new project `make infra-bootstrap` failed twice (Cloud Resource Manager off before the first plan; service accounts created before the IAM API was live) — fixed here (the script enables the APIs with gcloud first; service accounts depend on the APIs) — port the fix to agentic-dev-template
- 2026-11-22 cycle: `CycleReport.sent` is 0 when `execute` raises after sending some orders (the ledger is right) — don't rely on `report.sent` for anything but logs
- 2026-11-22 broker adapter (Phase 2): exception messages reach ERROR logs and the alert email — keep raw response bodies out of `BrokerError` text, and never run `run_cycle` against the demo API from CI (ADR-0014)
- 2026-11-21 order path (Phase 1 design): contracts now stop anything but `app` importing `execution` and anything but `execution`/`app` importing `brokers`; still to do — a read-only market-data port separate from the order port, and `execution` accepting only a risk-approved order type, with a test
- 2026-11-21 broker HTTP: `urllib`'s default redirect handler forwards `Authorization` to the redirect target (`scripts/phase0_api_check.py`, `app/flags.py` GCS reads) — the Trading 212 adapter must refuse redirects or drop credentials across origins; don't copy the phase0 opener
- 2026-11-21 phase0 script: far-away STOP/STOP_LIMIT buy prices come from `--ref-price`, so a GBP price for a GBX-quoted ETF fills immediately (demo only) — don't reuse that logic in the adapter; sanity-check ref price against `currentPrice`
- 2026-11-21 dependabot: uv updates skip agent-review and auto-merge on CI alone — add a `cooldown` (e.g. 7 days) to `.github/dependabot.yml`
- 2026-11-21 config: `pyproject.toml` is standard risk, so a PR can loosen ruff/mypy/pytest settings (e.g. `addopts = "--co"` makes unit tests a no-op) or point `[tool.uv.sources]`/`[[tool.uv.index]]` at a non-PyPI source for the gate tools; listing it would make every Dependabot bump high risk — move gate settings to dedicated files passed explicitly from `stack.mk` (`pytest -c`, `ruff --config`, `mypy --config-file`), list them, and add a `scripts/` check that `uv.lock` uses only the PyPI registry
- 2026-11-21 kit: the bootstrap skill's owner checklist still says "GitHub Pro" for every repo — misleading for public repos like this one — change it upstream in the kit repo, then `make kit-sync`
- 2026-11-21 github-setup: `scripts/github-setup.sh` doesn't set secret scanning, push protection or fork-PR approval — the owner sets them by hand (first-time-setup.md) — script them when next touching the file
- 2026-11-21 toolchain: `mise install` can't reach GitHub releases or python downloads from cloud sessions — gitleaks, actionlint and shellcheck are missing there — add the hosts to the cloud environment or install them in its setup script
