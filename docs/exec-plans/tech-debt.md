# Tech debt

Things noticed but deliberately left out of scope. One line each, newest first.
Format: `- YYYY-MM-DD <area>: <problem> — <impact> — <suggested fix>`

- 2026-11-21 deploy: `ci.yml` preview, `deploy.yml`, `scripts/smoke.sh`, `cloudrun-*.sh` and `make logs` assume a Cloud Run service with a URL — they can't deploy or check the job (docs/operations.md and docs/testing.md carry interim notes) — build the job variant with the Phase 2 job module (ADR-0011)
- 2026-11-21 risk-gate (pre-existing, high): `scripts/risk_gate.py` accepts `/approve-risk` from any comment posted under the owner's login; in cloud sessions the agent acts through the owner's identity via the Claude GitHub App, so only a guard-hook regex stops self-approval (bypassable via `gh api -F body=@file` or a script) — reject comments with non-null `performed_via_github_app`, or use a separate approver identity; owner decision (high-risk PR)
- 2026-11-21 flags (fix before any order path reads `new-orders`): the kill switch fails open in a job — each execution starts with no last good overrides, so a failed or timed-out Cloud Storage read, a 404 on the overrides object, a non-bool value or a missing `FLAGS_BUCKET` all mean the registry default (true), and an env `FLAG_NEW_ORDERS=on` beats a remote kill — for kill switches in the job, treat an unreadable or malformed source as off plus an alert, refuse to start without `FLAGS_BUCKET` outside local/test, don't let env override a remote off in prod; turn the strict-xfail tripwire `tests/app/test_flags.py::test_kill_switch_is_off_when_the_first_fetch_fails` into a passing test
- 2026-11-21 order path (Phase 1 design): contracts now stop anything but `app` importing `execution` and anything but `execution`/`app` importing `brokers`; still to do — a read-only market-data port separate from the order port, and `execution` accepting only a risk-approved order type, with a test
- 2026-11-21 broker HTTP: `urllib`'s default redirect handler forwards `Authorization` to the redirect target (`scripts/phase0_api_check.py`, `app/flags.py` GCS reads) — the Trading 212 adapter must refuse redirects or drop credentials across origins; don't copy the phase0 opener
- 2026-11-21 phase0 script: far-away STOP/STOP_LIMIT buy prices come from `--ref-price`, so a GBP price for a GBX-quoted ETF fills immediately (demo only) — don't reuse that logic in the adapter; sanity-check ref price against `currentPrice`
- 2026-11-21 agent-review: `anthropics/claude-code-action@v1` is a floating tag, and the hooks-off protection depends on its behaviour — pin it by commit SHA (`.claude/rules/workflows.md`)
- 2026-11-21 dependabot: uv updates skip agent-review and auto-merge on CI alone — add a `cooldown` (e.g. 7 days) to `.github/dependabot.yml`
- 2026-11-21 config: `pyproject.toml` is standard risk, so a PR can loosen ruff/mypy/pytest settings (e.g. `addopts = "--co"` makes unit tests a no-op) or point `[tool.uv.sources]`/`[[tool.uv.index]]` at a non-PyPI source for the gate tools; listing it would make every Dependabot bump high risk — move gate settings to dedicated files passed explicitly from `stack.mk` (`pytest -c`, `ruff --config`, `mypy --config-file`), list them, and add a `scripts/` check that `uv.lock` uses only the PyPI registry
- 2026-11-21 kit: the bootstrap skill's owner checklist still says "GitHub Pro" for every repo — misleading for public repos like this one — change it upstream in the kit repo, then `scripts/kit-sync.sh`
- 2026-11-21 github-setup: `scripts/github-setup.sh` doesn't set secret scanning, push protection or fork-PR approval — the owner sets them by hand (first-time-setup.md) — script them when next touching the file
- 2026-11-21 hooks: in a session that loads the kit as a plugin *and* reads `.claude/settings.json`, each hook runs twice — the stop gate runs `make check-fast` twice, in parallel, and one copy can consume `.agentic/allow-stop` while the other still blocks — drop the settings entries if cloud sessions start loading repo plugins
- 2026-11-21 toolchain: `mise install` can't reach GitHub releases or python downloads from cloud sessions — gitleaks, actionlint and shellcheck are missing there — add the hosts to the cloud environment or install them in its setup script
